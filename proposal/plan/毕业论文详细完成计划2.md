### 模块 10：评价审核Agent开发（14h）

| 技术项 | 具体工作 | 工时 |
|-------|---------|------|
| Agent类设计 | 创建 `RiskEvaluationAgent` 类（SPADE），接收人工评价结果，执行三项审核检测 | 2h |
| 异常检测行为 | 实现 `AnomalyDetectionBehaviour`（OneShotBehaviour）：①计算所有风险评分的方差，方差<阈值（如所有评分一致=不加区分）时标记异常；②检测单条评分偏离均值超过2个标准差的情况 | 4h |
| 矛盾检测行为 | 实现 `ConflictDetectionBehaviour`（OneShotBehaviour）：按风险类型分组→组内比较评分差异→同类风险评分差异>2级的标记为矛盾 | 4h |
| 遗漏检测行为 | 实现 `OmissionDetectionBehaviour`（OneShotBehaviour）：对比输入风险清单和评价结果→未被评价的风险项标记为遗漏 | 2h |
| 审核意见输出 | 汇总三项检测结果，生成结构化的审核意见列表（异常项、矛盾项、遗漏项），发送给人工复核 | 2h |

**审核Agent检测逻辑**：
```
输入：人工评价结果列表 [{risk_id, probability, impact, urgency}, ...]

检测1 — 异常检测：
  scores = [p*impact for each evaluation]
  if std(scores) < threshold:
      flag "评分方差过小，可能存在不加区分的评分行为"
  for each score in scores:
      if abs(score - mean) > 2*std:
          flag "风险X评分异常偏离"

检测2 — 矛盾检测：
  group evaluations by risk_type
  for each group:
      if max(probability) - min(probability) > 2:
          flag "同类风险'{type}'的概率评分差异过大({max-min}级)"

检测3 — 遗漏检测：
  identified_risks = load risk list from chapter 3
  evaluated_risks = {e.risk_id for e in evaluations}
  omitted = identified_risks - evaluated_risks
  if omitted:
      flag "以下风险未被评价: {omitted}"
```

### 模块 12：应对策略知识库构建（12h）

| 技术项 | 具体工作 | 工时 |
|-------|---------|------|
| 策略类型定义 | 定义四种应对策略类型及其适用场景：规避（核心风险不可控时）、转移（可通过外包/保险转移）、缓解（可采取措施降低概率/影响）、接受（低概率低影响，建议监控） | 2h |
| 策略规则编写 | 为每种风险类型×每个风险等级组合编写2-3条候选策略。例：技术可行性风险(高)→[规避]建议更换成熟技术方案；[缓解]引入外部技术顾问团队进行可行性评估；[转移]与高校/研究机构合作分担研发风险 | 6h |
| 策略JSON编码 | 将策略规则编码为结构化JSON：每条策略包含 `{strategy_id, risk_type, min_risk_level, strategy_type, measure, responsible_party, suggested_timeline, expected_effect}`。目标40-60条规则 | 4h |

**策略JSON结构示例**：
```json

  "strategies": [
    {
      "id": "STRAT-001",
      "risk_type": "技术可行性风险",
      "min_risk_level": 13,
      "strategy_type": "规避",
      "measure": "引入外部技术顾问团队进行独立技术可行性评估，若评估不通过则调整技术路线",
      "responsible_party": "技术负责人",
      "suggested_timeline": "2周内完成评估",
      "expected_effect": "降低技术不可行的决策风险"
    }
  ]
}
```

### 模块 13：策略生成Agent开发（20h）

| 技术项 | 具体工作 | 工时 |
|-------|---------|------|
| Agent类设计 | 创建 `StrategyGenerationAgent` 类（SPADE），使用FSMBehaviour实现状态机流转 | 2h |
| 评价结果接收状态 | FSM状态1 `RECEIVE_EVAL`：通过CyclicBehaviour监听XMPP消息，接收第四章输出的风险评价结果 | 3h |
| 策略匹配状态 | FSM状态2 `MATCH_STRATEGY`：加载策略规则库→遍历每条风险评价→按风险类型+等级阈值匹配策略规则→按风险优先级排序策略建议列表 | 5h |
| 策略组装状态 | FSM状态3 `ASSEMBLE_PLAN`：将匹配的策略按风险项分组，组装为结构化的策略计划表。同一风险有多种策略时按优先级排序（规避>转移>缓解>接受） | 4h |
| 消息发送状态 | FSM状态4 `SEND_RESULT`：将策略计划封装为JSON消息，发送给人机交互Agent或直接输出 | 3h |
| 状态流转逻辑 | 实现FSM的状态注册和转换：RECEIVE_EVAL→MATCH_STRATEGY→ASSEMBLE_PLAN→SEND_RESULT→RECEIVE_EVAL（等待下一批评价） | 3h |

**FSMBehaviour状态流转图**：
```
┌──────────────┐
│ RECEIVE_EVAL │ ← 等待评价结果消息
└──────┬───────┘
       │ 收到消息
       ▼
┌────────────────┐
│ MATCH_STRATEGY │  加载策略库，匹配策略
└──────┬─────────┘
       │ 匹配完成
       ▼
┌────────────────┐
│ ASSEMBLE_PLAN  │  组装策略计划表
└──────┬─────────┘
       │ 组装完成
       ▼
┌────────────────┐
│  SEND_RESULT   │  发送策略计划
└──────┬─────────┘
       │ 发送完成
       └──────→ RECEIVE_EVAL (循环)
```
