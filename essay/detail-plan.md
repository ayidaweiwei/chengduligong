## 一、论文概览

### 1.1 论文题目

基于工业数字空间的边缘计算设备智能中试研究

### 1.2 选题来源与核心概念

本选题来源于工程管理领域对边缘计算设备中试验证效率提升的实际需求。传统中试面临**周期长、验证效率低、设备数字化验证困难**三大痛点，迫切需要引入智能化手段重构中试流程。

### 1.3 核心概念界定：JVM = 边缘计算设备

本文最根本的概念设定：**在本研究中，JVM 运行时实例即边缘计算设备本身**。

```
传统工程视角（本文不采用）：
  物理边缘硬件 + JVM运行时 + 上层应用 → 对上层应用进行测试

本论文工程管理视角：
  JVM运行时 = 边缘计算设备
  ├─ JVM参数配置（堆大小、GC策略、线程池） = 设备的规格参数
  ├─ API端点（HTTP/gRPC/MQTT）            = 设备的对外接口
  ├─ 字节码执行逻辑                         = 设备的行为逻辑
  ├─ 吞吐量、延迟、内存占用                 = 设备的性能指标
  ├─ JAR构建产物                           = 设备的功能组件/制品
  └─ JVM异常（OOM、STW、死锁）             = 设备的故障模式
```

**为什么 JVM 可以等同于边缘计算设备？** 在工程管理视角下，边缘计算设备的本质是其运行时计算能力。JVM 作为该计算能力的完整载体，定义了设备的计算资源边界、对外接口规范、行为逻辑和性能特征。JVM 运行时的配置、行为和性能，就是该边缘计算设备的规格、行为和性能。这一概念设定使得本研究能够聚焦于设备的工程化中试验证方法，而非特定的底层硬件平台。

## 二、选题依据详细设计

### 2.1 研究背景（四层递进结构）

#### 2.1.1 第一层：工业数字空间的发展与CFD仿真服务

**提示词要点**：
- 工业4.0、智能制造背景下，工业数字空间（Industrial Digital Space）成为实现工业全要素数字化的重要载体
- 工业数字空间即工业数字孪生空间：将实体工厂、产线、设备完整映射为数字化数字模型，实现虚实同步仿真、数据互通
- CFD 作为工业数字空间内的**仿真服务**，提供虚实同步仿真、设备行为模拟、验证场景推演等核心仿真能力
- 数据底座（数据库、消息队列等公共组件）为CFD仿真服务提供数据基础设施支撑
- 工业数字空间如何解决传统工业中试中数据孤岛、系统异构、流程断裂的问题

**写作提示**：
```
从工业数字化转型切入 → 引出工业数字空间（数字孪生）概念 → 
CFD仿真服务作为核心仿真引擎 → 数据底座提供数据支撑 → 
数字空间为中试验证提供的三大能力（仿真推演、数据共享、流程贯通）
```

#### 2.1.2 第二层：边缘计算设备的普及与中试挑战

**提示词要点**：
- 5G、IoT推动下边缘计算设备数量爆发式增长
- 边缘计算设备的特点：资源受限、环境异构、实时性要求高、版本迭代频繁
- 中试（Pilot Testing）的定义与定位：产品从研发到量产之间的验证阶段，对设备的功能、性能、可靠性、兼容性等进行全面检验
- 传统中试面临的三大痛点：
  - **中试周期长**：人工设计验证场景、手动执行验证用例，周期冗长
  - **验证效率低**：验证环境搭建复杂，设备配置繁琐，验证结果人工汇总分析
  - **设备数字化验证困难**：边缘计算设备以JVM运行时为核心，在数字环境中完整复现其运行行为并进行充分验证面临巨大挑战

**写作提示**：
```
边缘计算设备市场规模数据 → 边缘设备以JVM运行时的技术特征 → 
中试在设备质量保障中的关键作用 → 传统中试的三大痛点
```

#### 2.1.3 第三层：AI Agent技术的成熟与验证领域应用机遇

**提示词要点**：
- 大语言模型（GPT-4、Claude等）的快速发展
- AI Agent从单一推理向多步骤自主任务执行的演进
- Agent + Skill + MCP架构在工程领域的成熟应用
- AI Agent在设备验证领域的潜在应用场景：
  - 验证场景自动生成（替代人工设计）
  - 验证执行自动编排（替代手动执行）
  - 验证结果智能分析（替代人工汇总）
  - 风险自动量化（替代经验判断）

**写作提示**：
```
LLM能力跃升 → Agent架构成熟（引用Wang 2024综述） →
Skill模块化 + MCP标准化协议 → Agent在设备验证领域四类应用 →
与传统人工中试的对比优势（效率提升、成本降低、一致性保证）
```

#### 2.1.4 第四层：事理知识图谱在验证场景生成中的潜力

**提示词要点**：
- 知识图谱从"实体关系型"向"事件逻辑型"（事理知识图谱）的演进
- 事理知识图谱的核心能力：描述事件之间的因果、时序、条件等逻辑关系
- 中试验证场景的本质：设备运行中可能发生的"风险事件"及其逻辑链路
- 基于事理知识图谱的验证场景生成逻辑：风险事件 → 因果链路推理 → 验证场景构建 → 验证用例生成

**写作提示**：
```
知识图谱演进路径 → 事理知识图谱的概念与特点 → 
中试验证场景的"事件驱动"特性 → "风险事件→验证场景"的知识驱动生成逻辑
```

#### 2.1.5 研究背景总结（提炼核心矛盾）

```
核心矛盾：
传统边缘计算设备中试（人工设计场景 + 手动执行验证 + 经验判断风险）
  VS
智能化中试需求（自动生成场景 + 自动编排执行 + 量化风险）

研究切入点：
以工业数字空间的CFD仿真服务与数据底座为基础，以事理知识图谱为知识驱动，以AI Agent为执行引擎，
构建"数据+知识+智能"三位一体的边缘计算设备(JVM)智能中试方法体系。
```

## 三、研究方案详细设计

### 3.1 研究内容（三大块→第3-5章）

```
研究内容一：工业数字空间中的CFD仿真服务与边缘计算设备建模（对应第3章）
  ├─ 子内容1.1：面向中试的CFD仿真服务架构设计
  │   - CFD仿真服务架构（仿真引擎层、设备行为建模层、场景推演层、虚实同步层）
  │   - 数据底座设计（数据存储层、消息中间件层、设备管理层、接口服务层）
  │   - 公共组件设计（数据库、消息队列、日志、监控、权限）
  │   - 数据模型标准化（设备元数据模型、验证数据模型、结果数据模型）
  ├─ 子内容1.2：边缘计算设备(JVM)资源模型设计
  │   - JVM设备数字化表示（JVM参数=设备规格、JAR制品=设备功能组件、依赖关系）
  │   - 设备能力模型（计算能力、存储能力、网络能力、技术栈）
  │   - 设备-CFD仿真服务交互协议设计
  └─ 子内容1.3：设备制品的数字化接入方案
```

### 3.4 创新点

#### 创新点1：架构创新 — 构建了"CFD仿真服务 + 事理知识图谱 + AI Agent编排"三位一体的边缘计算设备智能中试架构

```
创新阐述：
首次将工业数字空间中的CFD仿真服务、事理知识图谱和AI Agent编排进行系统性融合，
提出面向边缘计算设备(JVM)中试的"仿真服务层（CFD）→ 知识层（知识图谱）→
执行层（Agent编排）"三层智能中试架构。CFD仿真服务为设备中试提供了虚实同步仿真
和场景推演能力，知识图谱为验证场景生成提供了知识驱动能力，Agent编排为中试执行
提供了自动化编排能力，三者协同实现了中试全流程的数字化、知识化、智能化。

```

```
将事理知识图谱引入设备验证场景生成领域，构建"风险事件→因果链路推理→
```

```
- aggravate(Event_A, Event_B)：事件A加剧事件B的影响程度
- mitigate(Action_X, Event_B)：操作X减轻事件B的影响
```

```
  │   └─ 验证场景2.2：消息吞吐量-延迟联合验证
```

```
多维验证评价指标：

维度1：功能符合性（权重30%）
  ├─ AC通过率 = 通过的AC数 / 总AC数
  ├─ 验证用例通过率 = 通过的验证用例数 / 总验证用例数
  └─ 回归通过率 = 回归验证通过数 / 回归验证总数

维度2：性能表现（权重25%）
  ├─ 执行时间变化率 = (实测时间 - 基准时间) / 基准时间
  ├─ 内存占用变化率 = (实测内存 - 基准内存) / 基准内存
  ├─ CPU使用率变化率
  └─ 吞吐量（消息处理条数/秒）

维度3：风险覆盖度（权重25%）
  ├─ 风险场景覆盖率 = 已覆盖风险场景数 / 总风险场景数
  ├─ 高优先级风险覆盖完整性（必须100%）
  └─ 边界场景覆盖度

维度4：制品质量（权重20%）
  ├─ 圈复杂度
  ├─ 重复率
  ├─ 单元验证覆盖率
  └─ 静态分析违规数

综合评分公式：
Score = Σ(维度得分_i × 权重_i)
维度得分 = Σ(指标得分_ij × 指标权重_ij) / 指标满分
```

```
   - status (pending/running/passed/failed/skipped)
   - actual_result, error_log
   - performance_metrics

7. ValidationReport（验证报告）
   - report_id, artifact_id, execution_summary
   - dimension_scores (functional/performance/risk_coverage/artifact_quality)
   - overall_score, risk_warnings
   - generated_at
```

### 5.3 技术路线详细步骤

```
第1步：设备接入（Device Ingestion）
  ├─ GitHub Clone → Maven Build → JAR Artifact
  ├─ 解析 pom.xml → 提取设备规格信息（JVM参数、依赖等）
  ├─ 运行单元验证 → 采集初始验证数据
  └─ 写入工业数字空间（设备注册 + 设备制品元数据入库）

第2步：风险识别（Risk Identification）
  ├─ 风险识别Agent读取设备资源模型 + 制品元数据
  ├─ 匹配风险模式库 → 生成风险清单（含优先级）
  ├─ 人工审核确认风险清单
  └─ 写入CFD RiskEvent库 + 更新知识图谱

第3步：验证场景生成（Scenario Generation）
  ├─ 知识图谱引擎以风险事件为起点进行因果链路推理
  ├─ 生成验证场景列表（含前置条件、步骤、预期结果）
  ├─ 场景→用例自动转换
  ├─ 人工审核确认（重点审核高优先级场景）
  └─ 写入CFD ValidationScenario + ValidationCase库

第4步：验证编排执行（Validation Orchestration）
  ├─ 编排Agent读取验证场景列表 → 生成执行计划DAG
  ├─ 调度执行Agent按DAG顺序调用Skill+MCP工具
  ├─ 实时采集执行状态 + 性能指标（通过JMX/Prometheus）
  └─ 执行结果结构化写入CFD ValidationExecution库

第5步：结果评估报告（Evaluation & Reporting）
  ├─ 评估Agent读取全部执行结果
  ├─ 按评价指标体系计算各维度得分
  ├─ 加权计算综合评分
  ├─ 生成验证报告（含评分、风险预警、改进建议）
  └─ 更新知识图谱（新发现的缺陷模式/风险事件）
```
