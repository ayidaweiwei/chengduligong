### 2.2 第2章 相关理论与技术基础

#### 2.2.1 核心概念界定

```
- 代码重构（Code Refactoring）：改善代码内部结构而不改变外部行为
- 验收条件（Acceptance Criteria, AC）：需求可验证的通过标准
- AI Agent：具备自主感知、推理、执行能力的智能代理
- Skill：可复用的专业能力模块
- MCP（Model Context Protocol）：AI Agent 工具调用标准协议
- 多目标优化：同时优化多个可能冲突的目标函数
- Gurobi：高性能数学规划求解器
- 硬风险：功能正确性不满足（AC 不通过）
- 软风险：非功能属性不达标（性能、质量等）
```

#### 2.2.2 理论基础

```
- 代码重构理论（Martin Fowler 重构目录、重构原则）
- 多智能体系统理论（Agent/Skill/MCP 协作模型）
- 运筹学优化理论（线性规划、整数规划、多目标优化、Pareto 最优）
- Gurobi 求解器原理与 Python API
- 软件风险管理理论（硬风险/软风险分类框架）
```

### 2.3 第3章 需求驱动的代码重构 Agent 设计

#### 3.1 需求 AC 解析 Agent

```
工作内容：
- 设计需求 AC 描述格式（Gherkin 语法或结构化 JSON）
- 开发需求解析 Agent：提取变更点、影响范围分析
- 实现代码依赖关系分析 Skill
- 构建"Agent 解析 + 人工确认"的人机协同机制

技术实现：
- Agent 框架：LangChain / AutoGen / Claude Code Agent
- Skill 模块：代码静态分析（AST 解析）、依赖关系图构建
- MCP：代码库操作协议、文件读写协议
```

#### 3.2 代码重构 Skill 库

```
重构 Skill 分类：
- 结构重构 Skill：提取方法、移动类、拆分大文件
- 命名优化 Skill：变量名规范化、函数名语义化
- 性能优化 Skill：循环优化、缓存策略、延迟加载
- 架构调整 Skill：模块化重构、依赖注入、接口抽象

Skill 实现要点：
- 每个 Skill 定义输入输出规范
- Skill 组合机制（DAG 编排）
- 回滚机制（重构失败恢复）
```

```
MCP 能力：
- 文件系统 MCP：读取源码、写入重构后代码
- Git 操作 MCP：创建分支、提交变更、差异对比
- LLM 调用 MCP：大模型推理、代码生成
- 代码分析 MCP：调用静态分析工具（pylint、eslint 等）
```

#### 3.4 整体架构设计

```
层次划分：
- 需求层：AC 解析、变更影响分析

- 执行层：重构 Skill 编排、MCP 调用
- 验证层：AC 测试、性能检测、代码质量检测
```

### 2.4 第4章 基于 Gurobi 的多目标重构优化模型

#### 4.1 问题建模

```
输入：
- 原始代码（含 AST、依赖关系）
- 需求变更点（AC 差异分析）
- 重构约束（时间预算、质量阈值、性能要求）

输出：
- 最优重构方案序列
- 重构成本-收益分析
```

#### 4.2 目标方程设计

```
多目标函数：
min F(x) = [f1(x), f2(x), f3(x)]

其中：
f1(x) = 重构成本（修改代码行数、涉及文件数、估计工时）
f2(x) = -代码质量提升（圈复杂度降低、重复率降低、可维护性提升）[取负]
f3(x) = 性能影响（执行时间变化、资源占用变化）

可采用加权和形式：
min F(x) = w1·f1(x) + w2·(-f2(x)) + w3·f3(x)
（w1, w2, w3 通过专家评分法或 AHP 确定权重）
```

#### 4.3 约束变量与值域

```
约束条件：
C1: AC 满足约束 → 重构后必须通过所有 AC 测试（布尔约束）
C2: 代码质量约束 → 圈复杂度 ≤ 10，重复率 ≤ 5%（值域约束）
C3: 性能约束 → 执行时间增加 ≤ 10%，内存占用增加 ≤ 15%（值域约束）
C4: 重构范围约束 → 修改文件数 ≤ N（值域约束）
C5: 依赖关系约束 → 不破坏现有接口契约（逻辑约束）

决策变量：
x_ij ∈ {0, 1}：是否对模块 i 应用第 j 种重构策略
k_ij：重构策略 j 在模块 i 上的应用程度（连续变量，0-1）
```

#### 4.4 Gurobi 求解实现

```
求解流程：
1. 构建优化模型对象（gurobipy.Model）
2. 添加决策变量（变量类型、上下界）
3. 设置目标函数（多目标加权或 Pareto）
4. 添加约束条件（线性约束、逻辑约束）
5. 设置求解参数（时间限制、MIPGap、迭代次数）
6. 调用 model.optimize() 求解
7. 解析结果，生成重构方案

关键代码结构示意：
import gurobipy as gp
from gurobipy import GRB

model = gp.Model("CodeRefactoring")

# 变量定义
x = model.addVars(modules, strategies, vtype=GRB.BINARY, name="x")
k = model.addVars(modules, strategies, lb=0, ub=1, name="k")

# 目标函数
model.setObjective(
    w1 * cost(x, k) + w2 * quality_loss(x, k) + w3 * performance_impact(x, k),
    GRB.MINIMIZE
)

# 约束
model.addConstrs(ac_satisfied(x, k) == 1 for ...)
model.addConstrs(cyclomatic_complexity(x, k) <= 10 for ...)
model.addConstrs(time_increase(x, k) <= 0.1 for ...)

# 求解
model.optimize()

# 输出方案
for m in modules:
    for s in strategies:
        if x[m, s].X > 0.5:
            print(f"Apply {s} to {m}")
```

### 2.5 第5章 重构效果三维验证与风险管理

#### 5.1 验证框架

```
三维度验证 + 双风险管控：
├─ 维度1：功能正确性验证（硬风险）
│  └─ AC 测试通过率、回归测试通过率
├─ 维度2：性能效率验证（软风险）
│  └─ 执行时间、内存占用、CPU 使用率、IO 吞吐量
└─ 维度3：代码质量验证（软风险）
   └─ 圈复杂度、代码重复率、可维护性指数、技术债务
```

#### 5.2 AC 验证（硬风险控制）

```
验证内容：
- 原 AC 测试全部通过（无回归）
- 新增需求 AC 测试通过
- 边界条件测试通过

风险定义：
- 硬风险：AC 结果不符合预期，功能正确性不满足
- 风险等级：高（影响系统可用性）
- 应对策略：自动化测试 + 人工复查 + 回滚机制

验证方法：
- 自动化测试框架（pytest / JUnit）
- AC 测试用例自动生成（基于需求描述）
- 测试覆盖率统计（目标：≥80%）
```

#### 5.3 性能验证（软风险控制）

```
指标定义：
- 执行时间变化率 = (重构后时间 - 重构前时间) / 重构前时间
- 内存占用变化率 = (重构后内存 - 重构前内存) / 重构前内存
- CPU 使用率变化率 = (重构后 CPU - 重构前 CPU) / 重构前 CPU

风险定义：
- 软风险：代码资源占用高、异常报错、执行效率低
- 风险等级：中（影响用户体验但系统可运行）
- 应对策略：性能基线对比 + 阈值告警 + 优化 Skill 选择

性能基准：
- 预热：执行 N 次取稳定值
- 多轮：测量 10 次取均值
- 负载：基准负载 + 压力负载
```

#### 5.4 代码质量验证（软风险控制）

```
质量指标：
- 圈复杂度（Cyclomatic Complexity）：<10 为优，10-20 为中，>20 为差
- 代码重复率（Duplication）：<5% 为优，5-10% 为中，>10% 为差
- 可维护性指数（Maintainability Index）：>85 为优，65-85 为中，<65 为差
- 技术债务（Technical Debt）：用 SonarQube 等工具计算

风险定义：
- 软风险：代码质量下降、可维护性降低、技术债务增加
- 风险等级：中（长期影响但短期可接受）
- 应对策略：质量阈值约束 + 自动修复 Skill + 定期审查

验证工具：
- 静态分析：SonarQube、pylint、ESLint
- 复杂度分析：Radon、Lizard
- 重复检测：jscpd、CPD
```
