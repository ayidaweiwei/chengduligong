# 科创项目风险评价体系文档

> 本文档整理自 `/essay/example/` 目录下的7张图片，内容为科创项目风险评价的核心指标框架与模型设计。

---

## 一、风险概念界定

在科创项目的全生命周期管理中，**技术研发风险**与**技术迭代风险**是两个截然不同却又紧密相连的维度。

### 技术研发风险
- 聚焦于**从0到1的开发阶段**
- 核心在于"**能不能做出来**"

### 技术迭代风险
- 聚焦于**从1到N的演进与应用阶段**
- 核心在于"**做出来能用多久、会不会被淘汰**"

> 来源：山东省科学技术厅

## 二、技术研发风险评价体系（R&D Risk Assessment）

聚焦从0到1的"诞生期"，评估技术**能不能做出来、做出来能不能用**，关键看「技术实现的难度、现有能力的缺口、资源投入的风险」。

### 1. 技术可行性风险（Technical Feasibility）
核心判断：**现有科学原理能否支撑、关键技术瓶颈能否突破**
- 1.1 原理成熟度：是否处于实验室探索阶段、已验证概念还是已形成技术原型
- 1.2 技术瓶颈复杂度：关键技术难题的数量、攻克难度，是否依赖多学科交叉突破
- 1.3 替代技术路径：是否存在备选技术方案，单一技术路径失败的风险程度

### 2. 团队与能力风险（Team & Capability）
核心判断：**研发团队是否具备完成该技术突破的能力**
- 2.1 核心人员匹配度：核心研发人员的专业背景、技术积累与项目需求的契合度
- 2.2 研发经验：团队是否有同类/同复杂度技术的成功研发经验
- 2.3 组织协同能力：跨部门/跨团队协作的顺畅度，技术决策的效率

### 3. 资源与投入风险（Resource & Budget）
核心判断：**所需资源是否可及、投入是否可控、超支风险如何**
- 3.1 资金需求强度：研发总投入规模、分阶段投入计划，资金链断裂风险
- 3.2 关键设备/材料可获得性：是否依赖稀缺设备、进口垄断材料，供应稳定性
- 3.3 时间周期可控性：研发周期预估的合理性，延期风险及影响程度

### 4. 知识产权风险（IP & Compliance）
核心判断：**是否存在侵权风险、自有知识产权布局能否形成壁垒**
- 4.1 专利壁垒：核心技术专利的布局情况，是否落入他人专利保护范围
- 4.2 技术秘密保护：核心技术秘密的保护措施，泄密风险
- 4.3 合规与伦理：是否符合行业监管要求、伦理规范（尤其涉及AI、生物等领域）

### 5. 用户/需求匹配风险（User-Market Fit）
补充前置验证：**即使技术做成，是否真的解决用户痛点**
- 5.1 需求真实性：用户需求是"伪需求"还是"刚性痛点"，付费意愿验证
- 5.2 技术适用性：技术方案与用户场景的匹配度，是否存在"技术过度"或"技术不足"

## 三、技术迭代风险评价体系（Technology Iteration Risk）

聚焦从1到N的"进化期"，评估技术**能不能一直活下去、会不会被更快淘汰**，关键看「技术本身的进化潜力、外部技术替代的威胁、用户与场景的持续适配能力」。

### 1. 生命周期阶段风险（Lifecycle Maturity）
核心判断：**当前技术处于什么生命周期阶段，离技术天花板还有多远**
- 1.1 技术演进阶段判定：导入期→成长期→成熟期→衰退期，当前位置及依据
- 1.2 技术迭代速度预估：未来1-3年技术性能提升的空间、迭代频率
- 1.3 技术极限距离：现有技术路线接近物理/理论极限的程度，继续突破的难度

### 2. 替代技术威胁风险（Disruptive Substitution）
核心判断：**是否有破坏性技术正在或可能替代现有技术**
- 2.1 潜在替代技术识别：新原理/新技术路径的出现（如AI对传统算法的替代）
- 2.2 替代技术性价比：替代技术在性能、成本、用户体验上的优势对比
- 2.3 替代壁垒高低：用户从现有技术切换到替代技术的成本、习惯依赖程度

### 3. 生态系统依赖风险（Ecosystem Dependence）
核心判断：**技术是否依附于某个生态系统，生态变化的风险**
- 3.1 上游依赖：对核心零部件、开源框架、上游技术授权的依赖程度，被"卡脖子"风险
- 3.2 下游适配：技术演进是否与下游应用场景的变化同频，用户迁移成本
- 3.3 标准/协议锁定：是否纳入主流标准/协议，还是孤立发展，面临被边缘化风险

### 4. 用户与场景持续适配风险（User Scenario Evolution）
核心判断：**用户需求、应用场景是否在快速变化，现有技术能否跟上**
- 4.1 用户需求漂移：用户核心需求是否发生变化，现有技术是否持续满足
- 4.2 场景扩展性：技术能否从单一场景拓展到多场景，支撑第二增长曲线
- 4.3 竞品技术追赶：竞品技术迭代速度，是否存在被反超的风险

## 四、评价方案一：基于"内外双驱"的系统动力学架构（最推荐用于学术论文）

> 一句话总结：把"技术迭代"视为**内部技术进化（S曲线）** 与 **外部技术替代（颠覆者进入）** 共同作用的结果，构建因果循环图，仿真模拟风险演变。

### 一、内部技术进化子系统（内因）

#### A1. 技术能力积累维度
- A1.1 研发投入强度 → 技术知识存量积累 → 技术性能提升
- A1.2 技术性能提升 → 市场反馈/数据积累 → 进一步优化方向
- A1.3 核心人才保留 → 技术迭代延续性 → 技术路线不中断

#### A2. 技术S曲线位置维度
- A2.1 当前技术成熟度 → 离技术天花板距离 → 边际改进收益递减速度
- A2.2 边际改进收益 → 继续投入意愿 → 研发资源投入调整

#### A3. 技术架构延展性维度
- A3.1 模块化设计程度 → 技术升级兼容性 → 迭代成本高低
- A3.2 接口开放程度 → 生态参与度 → 外部创新反哺

### 二、外部技术替代子系统（外因）

#### B1. 替代技术威胁维度
- B1.1 新原理技术出现 → 替代技术性能追赶 → 市场份额挤压
- B1.2 替代技术成本下降 → 替代性价比凸显 → 用户迁移加速

#### B2. 用户需求演变维度
- B2.1 用户需求升级 → 原有技术性能缺口 → 倒逼技术迭代或切换
- B2.2 新场景出现 → 技术适用性重新评估 → 边缘领域被替代

#### B3. 竞争格局演变维度
- B3.1 竞品技术投入 → 技术差距缩小/拉大 → 竞争地位变化
- B3.2 标准/专利布局 → 技术话语权变化 → 路径依赖强化/打破

### 三、内外耦合的风险传导机制
- C1. 内部迭代滞后 → 外部替代窗口打开 → 替代风险加速放大
- C2. 外部替代压力 → 倒逼内部研发资源倾斜 → 内部迭代加速（或资源分散陷入混乱）
- C3. 用户从"等待迭代"转向"尝试替代" → 正反馈循环触发 → 现有技术快速衰退

## 五、评价方案二：基于TRL（技术就绪度）的技术演进模型（适合实证研究）

> 一句话总结：把技术演进映射到**TRL 1-9级标准刻度**，计算「技术迭代速度（ΔTRL/Δt）」和「技术迭代综合风险指数（TRI）」，既可横向对比多个项目，也可纵向跟踪单一项目。

### 1. TRL九级标尺映射（锚定迭代节点）

| TRL等级 | 定义 | 迭代关键里程碑 |
|---------|------|----------------|
| TRL 1-3 | 实验室阶段 | 原理验证→概念验证→实验室原型 |
| TRL 4-6 | 中试阶段 | 实验室环境验证→模拟环境验证→真实/近真环境验证 |
| TRL 7-9 | 产业化阶段 | 真实环境原型→小批量试产→规模化量产/商业化 |

### 2. 综合风险指数（TRI）计算公式

```
TRI = w1 × R&D_Risk + w2 × RPI + w3 × TTR_Risk
```

其中：
- **R&D_Risk**：当前技术本身的研发/迭代难度系数（取值0-1）
- **RPI**：替代威胁指数（Replacement Threat Index，取值0-1）
- **TTR_Risk**：时间窗口风险（Time-To-Replacement，取值0-1）
- **w1、w2、w3**：通过AHP/专家打分确定的权重

### 3. 风险等级判定与动态迭代权重调整

在实际应用中，建议**随着TRL提升动态调整权重**（如TRL 1-3时w1权重更高，TRL 7-9时w2、w3权重更高），并结合「替代技术的TRL进展速度」进一步修正。

## 六、评价方案三：二维风险象限矩阵（Matrix Layout）

如果您需要对多个科创项目进行横向对比（筛选和投资决策），可以将研发风险与迭代风险作为X轴和Y轴，构建一个四象限矩阵评价体系。

### 坐标系定义
- **横轴（X）**：技术研发风险值（从低到高）
- **纵轴（Y）**：技术迭代风险值（从低到高）

### 四象限划分

```
                    ▲ 技术迭代风险 (Y)
                    |
    【象限Ⅱ：短命高难型】 | 【象限Ⅰ：双重高危型】
    研发难，且极易被淘汰 | 研发难度大，技术变过快
   （审慎投资/极高风险） | （战略放弃/或国家级攻关）
                    |
                    |
--------------------+------------------------→ 技术研发风险 (X)
                    |
                    |
    【象限Ⅲ：安全稳健型】 | 【象限Ⅳ：长寿高壁垒型】
    技术成熟，迭代极慢 | 研发虽难，但一旦做出来
   （传统产业/低风险） | 技术生命周期极长（黄金象限）
                    |
```

## 七、核心量化评价工具：TRL/MRL矩阵

针对技术研发风险，学界与业界最通用的评价方法是**技术就绪度（TRL）**与**制造成熟度（MRL）**双维矩阵。

> 来源：www.idpc.org.cn

### 风险评级标准

| TRL/MRL等级 | 阶段描述 | 风险评级 |
|-------------|---------|---------|
| TRL ≤ 4 / MRL ≤ 4 | 处于实验室或概念验证阶段 | **高** |
| TRL 5~6 / MRL 5~6 | 处于模拟环境或原型样机阶段 | **中** |
| TRL ≥ 7 / MRL ≥ 7 | 处于真实环境验证或小批量试产阶段 | **低** |

> 来源：www.idpc.org.cn
